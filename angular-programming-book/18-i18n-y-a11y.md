# Capítulo 18: Internacionalización (i18n) y Accesibilidad (a11y)

> "Una aplicación verdaderamente profesional no es solo la que funciona bien, es la que funciona bien para todos: en cualquier idioma, en cualquier país y para cualquier persona, independientemente de sus capacidades."

La internacionalización y la accesibilidad no son features opcionales ni "nice-to-haves" que se añaden al final del proyecto. Son requisitos fundamentales para cualquier aplicación empresarial: la i18n porque tu empresa opera (o operará) en múltiples mercados, y la a11y porque es un requisito legal en la Unión Europea (European Accessibility Act 2025), en Estados Unidos (ADA) y porque es simplemente lo correcto.

Angular es uno de los frameworks con mejor soporte nativo para ambas disciplinas. Incluye un sistema de i18n integrado en el compilador AOT que genera builds optimizados por locale, y el CDK A11y proporciona utilidades de accesibilidad de nivel industrial.

---

## 18.1 Angular i18n Nativo: Compilación Multi-Idioma

### Filosofía: Una Build por Locale

El sistema de i18n nativo de Angular funciona **en tiempo de compilación**: extraes los textos marcados de tus plantillas a archivos de traducción (XLIFF o XMB), los traductores profesionales los traducen, y el compilador AOT genera un bundle optimizado separado para cada idioma. Esto significa:

* **Rendimiento máximo**: No hay overhead de runtime. Los textos ya están incrustados en el HTML compilado.
* **SEO perfecto**: Cada locale tiene su propio HTML estático con textos nativos.
* **Desventaja**: Necesitas un build y un despliegue separado por idioma.

### Paso 1: Marcar Textos para Traducción

Usa el atributo `i18n` en cualquier elemento HTML:

```html
<!-- Texto simple -->
<h1 i18n="Título de la página principal">Bienvenido a TechStore</h1>

<!-- Con descripción y contexto para el traductor -->
<p i18n="Descripción|Subtítulo en la página de inicio@@homeSubtitle">
  Encuentra los mejores productos de tecnología al mejor precio.
</p>

<!-- Atributos -->
<img src="logo.png" i18n-alt="Texto alternativo del logo@@logoAlt" alt="Logo de TechStore">

<!-- Placeholder con i18n -->
<input i18n-placeholder="Placeholder del campo de búsqueda@@searchPlaceholder" 
       placeholder="Buscar productos...">
```

### Paso 2: Extraer Textos

```bash
ng extract-i18n --output-path src/locale --format xlf
```

Esto genera `src/locale/messages.xlf` con todos los textos marcados:

```xml
<trans-unit id="homeSubtitle" datatype="html">
  <source>Encuentra los mejores productos de tecnología al mejor precio.</source>
  <context-group purpose="location">
    <context context-type="sourcefile">src/app/home/home.component.html</context>
    <context context-type="linenumber">5</context>
  </context-group>
  <note priority="1" from="description">Subtítulo en la página de inicio</note>
  <note priority="1" from="meaning">Descripción</note>
</trans-unit>
```

### Paso 3: Traducir

Copia el archivo para cada idioma y traduce los `<source>` a `<target>`:

```xml
<!-- src/locale/messages.en.xlf -->
<trans-unit id="homeSubtitle" datatype="html">
  <source>Encuentra los mejores productos de tecnología al mejor precio.</source>
  <target>Find the best technology products at the best price.</target>
</trans-unit>
```

### Paso 4: Configurar las Builds por Locale

```json
// angular.json
{
  "projects": {
    "techstore": {
      "i18n": {
        "sourceLocale": "es",
        "locales": {
          "en": "src/locale/messages.en.xlf",
          "fr": "src/locale/messages.fr.xlf",
          "de": "src/locale/messages.de.xlf"
        }
      },
      "architect": {
        "build": {
          "options": {
            "localize": true
          }
        }
      }
    }
  }
}
```

```bash
# Compilar todos los idiomas simultáneamente
ng build --localize

# Resultado: dist/techstore/es/, dist/techstore/en/, dist/techstore/fr/, dist/techstore/de/
```

## 18.2 Pluralización y Género con ICU Message Format

El ICU Message Format es un estándar internacional para manejar plurales, géneros y selecciones condicionales en traducciones:

### Pluralización

```html
<p i18n>
  {cantidadProductos, plural,
    =0 {No hay productos en tu carrito.}
    =1 {Tienes 1 producto en tu carrito.}
    other {Tienes {{cantidadProductos}} productos en tu carrito.}
  }
</p>
```

### Selección de Género

```html
<p i18n>
  {genero, select,
    masculino {Él ha actualizado su perfil.}
    femenino {Ella ha actualizado su perfil.}
    other {Ha actualizado su perfil.}
  }
</p>
```

## 18.3 Alternativas de i18n en Runtime: Transloco

Para aplicaciones que necesitan cambiar de idioma **sin recargar la página**, el i18n nativo de Angular no es adecuado (requiere navegar a una build diferente). Las alternativas de runtime más populares son:

### Transloco (Recomendado)

```bash
ng add @jsverse/transloco
```

```typescript
// app.config.ts
import { provideTransloco } from "@jsverse/transloco";
import { TranslocoHttpLoader } from "./transloco-http-loader";

export const appConfig: ApplicationConfig = {
  providers: [
    provideTransloco({
      config: {
        availableLangs: ["es", "en", "fr"],
        defaultLang: "es",
        reRenderOnLangChange: true,
        prodMode: !isDevMode()
      },
      loader: TranslocoHttpLoader
    })
  ]
};
```

Archivos de traducción JSON:
```json
// assets/i18n/es.json
{
  "catalogo": {
    "titulo": "Catálogo de Productos",
    "filtros": {
      "buscar": "Buscar productos...",
      "categoria": "Categoría",
      "todas": "Todas"
    },
    "producto": {
      "agregar": "Agregar al carrito",
      "agotado": "Agotado",
      "enStock": "En stock ({{cantidad}} uds.)",
      "pocasUnidades": "¡Solo quedan {{cantidad}}!"
    }
  }
}
```

Uso en plantillas:
```html
<h1>{{ "catalogo.titulo" | transloco }}</h1>
<input [placeholder]="'catalogo.filtros.buscar' | transloco">

<!-- Con parámetros dinámicos -->
<p>{{ "catalogo.producto.enStock" | transloco:{ cantidad: producto().stock } }}</p>

<!-- Cambiar idioma en runtime -->
<select (change)="cambiarIdioma($event)">
  <option value="es">Español</option>
  <option value="en">English</option>
  <option value="fr">Français</option>
</select>
```

```typescript
import { inject } from "@angular/core";
import { TranslocoService } from "@jsverse/transloco";

// En el componente:
private readonly transloco = inject(TranslocoService);

cambiarIdioma(event: Event): void {
  const idioma = (event.target as HTMLSelectElement).value;
  this.transloco.setActiveLang(idioma);
}
```

### Comparativa: i18n Nativo vs. Transloco

| Criterio | Angular i18n Nativo | Transloco |
|---|---|---|
| **Cambio de idioma** | Requiere navegar a otra build | En runtime, sin recarga |
| **Rendimiento** | Máximo (textos compilados) | Bueno (carga JSON bajo demanda) |
| **SEO** | Perfecto (HTML estático por locale) | Requiere SSR para cada locale |
| **Complejidad de deploy** | Alta (N builds = N deploys) | Baja (1 build + N archivos JSON) |
| **ICU Messages** | ✅ Nativo | ✅ Con plugin |
| **Lazy Loading** | ✅ Por build | ✅ Por scope |

## 18.4 Formateo Localizado de Fechas, Números y Monedas

Angular incluye pipes de formateo que respetan el locale activo:

```html
<!-- Registrar los datos de locale en app.config.ts -->
```

```typescript
// app.config.ts
import { registerLocaleData } from "@angular/common";
import localeEs from "@angular/common/locales/es";
import localeFr from "@angular/common/locales/fr";
import localeDe from "@angular/common/locales/de";
import { LOCALE_ID } from "@angular/core";

registerLocaleData(localeEs);
registerLocaleData(localeFr);
registerLocaleData(localeDe);

export const appConfig: ApplicationConfig = {
  providers: [
    { provide: LOCALE_ID, useValue: "es-ES" }
  ]
};
```

```html
<!-- Fechas -->
<p>{{ hoy | date:'fullDate' }}</p>
<!-- es-ES: "martes, 20 de mayo de 2025" -->
<!-- en-US: "Tuesday, May 20, 2025" -->

<!-- Números -->
<p>{{ 1234567.89 | number:'1.2-2' }}</p>
<!-- es-ES: "1.234.567,89" -->
<!-- en-US: "1,234,567.89" -->

<!-- Monedas -->
<p>{{ 1499.99 | currency:'EUR':'symbol':'1.2-2' }}</p>
<!-- es-ES: "1.499,99 €" -->
<!-- en-US: "€1,499.99" -->
```

## 18.5 Accesibilidad (a11y): Principios WCAG y ARIA

### Los 4 Principios WCAG 2.1

| Principio | Significado | Ejemplo en Angular |
|---|---|---|
| **Perceptible** | La información debe ser presentable de formas que los usuarios puedan percibir | Texto alternativo en imágenes, contraste de colores |
| **Operable** | La interfaz debe ser navegable con teclado | Focus management, skip links |
| **Comprensible** | La información debe ser entendible | Mensajes de error claros, labels descriptivos |
| **Robusto** | El contenido debe ser interpretable por tecnologías asistivas | HTML semántico, roles ARIA correctos |

### Roles y Atributos ARIA Esenciales

```html
<!-- Navegación principal -->
<nav aria-label="Navegación principal">
  <ul role="menubar">
    @for (item of menuItems(); track item.path) {
      <li role="menuitem">
        <a [routerLink]="item.path" [attr.aria-current]="isActive(item) ? 'page' : null">
          {{ item.label }}
        </a>
      </li>
    }
  </ul>
</nav>

<!-- Formulario accesible -->
<form aria-label="Formulario de contacto">
  <div>
    <label for="email">Correo electrónico</label>
    <input id="email" type="email" formControlName="email"
           [attr.aria-invalid]="emailControl.invalid && emailControl.touched"
           [attr.aria-describedby]="emailControl.invalid ? 'email-error' : null">
    @if (emailControl.invalid && emailControl.touched) {
      <p id="email-error" role="alert" class="text-red-500 text-sm">
        Por favor, introduce un correo electrónico válido.
      </p>
    }
  </div>
</form>

<!-- Región dinámica que anuncia cambios a lectores de pantalla -->
<div aria-live="polite" aria-atomic="true" class="sr-only">
  {{ mensajeAccesible() }}
</div>

<!-- Botón con icono (sin texto visible) -->
<button aria-label="Cerrar diálogo" (click)="cerrar()">
  <span aria-hidden="true">✕</span>
</button>
```

### CDK A11y: FocusTrap, LiveAnnouncer y FocusMonitor

```typescript
import { Component, inject, AfterViewInit, viewChild, ElementRef } from "@angular/core";
import { A11yModule, LiveAnnouncer, FocusTrap, FocusTrapFactory } from "@angular/cdk/a11y";

@Component({
  selector: "app-modal-accesible",
  standalone: true,
  imports: [A11yModule],
  template: `
    <!-- cdkTrapFocus: el foco del teclado queda atrapado dentro del modal -->
    <div cdkTrapFocus [cdkTrapFocusAutoCapture]="true" role="dialog" aria-modal="true"
         aria-labelledby="modal-titulo" class="p-6 bg-white rounded-lg shadow-xl">
      <h2 id="modal-titulo">Confirmar acción</h2>
      <p>¿Estás seguro de que deseas continuar?</p>
      <div class="flex gap-2 mt-4">
        <button (click)="cancelar()" cdkFocusInitial>Cancelar</button>
        <button (click)="confirmar()">Confirmar</button>
      </div>
    </div>
  `
})
export class ModalAccesibleComponent {
  private readonly announcer = inject(LiveAnnouncer);

  confirmar(): void {
    // Anuncia a los lectores de pantalla que la acción se completó
    this.announcer.announce("Acción confirmada exitosamente", "assertive");
  }

  cancelar(): void {
    this.announcer.announce("Acción cancelada", "polite");
  }
}
```

### FocusMonitor: Detectar Cómo se Obtuvo el Foco

```typescript
import { Component, inject, AfterViewInit, viewChild, ElementRef, OnDestroy } from "@angular/core";
import { FocusMonitor, FocusOrigin } from "@angular/cdk/a11y";

@Component({
  selector: "app-boton-inteligente",
  standalone: true,
  template: `<button #miBoton class="px-4 py-2 rounded">Mi Botón</button>`
})
export class BotonInteligenteComponent implements AfterViewInit, OnDestroy {
  private readonly focusMonitor = inject(FocusMonitor);
  private readonly botonRef = viewChild.required<ElementRef>("miBoton");

  ngAfterViewInit(): void {
    this.focusMonitor.monitor(this.botonRef().nativeElement).subscribe((origin: FocusOrigin) => {
      if (origin === "keyboard") {
        // El usuario llegó con Tab → mostrar anillo de foco visible
        console.log("Foco por teclado: mostrar indicador visual");
      } else if (origin === "mouse") {
        // El usuario hizo clic → no mostrar anillo de foco
        console.log("Foco por ratón: ocultar indicador visual");
      }
    });
  }

  ngOnDestroy(): void {
    this.focusMonitor.stopMonitoring(this.botonRef().nativeElement);
  }
}
```

## 18.6 Auditoría de Accesibilidad

### Herramientas Automáticas

| Herramienta | Tipo | Qué detecta |
|---|---|---|
| **Lighthouse (Chrome DevTools)** | Automática | Score a11y, contrastes, ARIA inválidos, labels faltantes |
| **axe-core / axe DevTools** | Automática + Extensión | Errores WCAG con explicación detallada y sugerencias de fix |
| **eslint-plugin-jsx-a11y** | Linting estático | Errores de ARIA y a11y en tiempo de compilación |
| **Playwright + axe** | Automated Testing | Tests E2E de accesibilidad en CI/CD |

### Test E2E de Accesibilidad con Playwright + axe-core

```typescript
// e2e/a11y.spec.ts
import { test, expect } from "@playwright/test";
import AxeBuilder from "@axe-core/playwright";

test.describe("Auditoría de Accesibilidad", () => {
  test("la página principal debe pasar la auditoría WCAG 2.1 AA", async ({ page }) => {
    await page.goto("/catalogo");

    const results = await new AxeBuilder({ page })
      .withTags(["wcag2a", "wcag2aa"]) // WCAG 2.1 nivel A y AA
      .analyze();

    // Mostrar violaciones encontradas para depuración
    if (results.violations.length > 0) {
      console.log("Violaciones de accesibilidad:");
      results.violations.forEach(v => {
        console.log(`- ${v.id}: ${v.description} (${v.impact})`);
        v.nodes.forEach(n => console.log(`  → ${n.html}`));
      });
    }

    expect(results.violations).toHaveLength(0);
  });
});
```

## Resumen del Capítulo

* **Angular i18n nativo** genera builds optimizados por locale en tiempo de compilación, con rendimiento y SEO máximos pero requiriendo un deploy separado por idioma.
* **Transloco** permite cambiar de idioma en runtime sin recargar la página, ideal para SPAs con selector de idioma.
* El **ICU Message Format** resuelve pluralización y selección de género de forma estandarizada e internacionalmente correcta.
* Los pipes `DatePipe`, `DecimalPipe` y `CurrencyPipe` formatean automáticamente según el `LOCALE_ID` registrado.
* **WCAG 2.1** define 4 principios (Perceptible, Operable, Comprensible, Robusto) con 3 niveles de conformidad (A, AA, AAA).
* Los atributos **ARIA** (`aria-label`, `aria-describedby`, `aria-live`, `role`) son esenciales para que los lectores de pantalla interpreten correctamente la interfaz.
* El **CDK A11y** proporciona `FocusTrap` para modales, `LiveAnnouncer` para anuncios a lectores de pantalla y `FocusMonitor` para distinguir el origen del foco.
* La auditoría automatizada con **axe-core + Playwright** en CI/CD garantiza que las regresiones de accesibilidad se detecten antes de llegar a producción.
